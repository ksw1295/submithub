# SubmitHub 심사위원 시연 가이드 (5분 안내서)

과제 제출을 **Git 버전처럼 관리**하고, 교수의 **줄 단위 코드 피드백을 시스템이 자동 추적**하며, **표절 검사와 자동 채점**을 제공하는 SubmitHub의 핵심 기능을 5분 만에 직접 체험하실 수 있는 안내서입니다.

---

## 1. 접속 정보 및 테스트 계정

- **서비스 접속 주소**: `https://submithub.duckdns.org` (로컬 환경: `http://localhost:8080`)
- **백업 시연 동영상**: `[시연 동영상 바로가기 (YouTube/Google Drive) - 심사 시 별도 링크 제공]`

| 구분 | 아이디 | 비밀번호 | 역할 및 특징 |
|---|---|:---:|---|
| **담당 교수** | `prof` | **[별도 전달]** | 과제 등록, 코드 줄 리뷰, 표절 검사 실행, 통계 대시보드 확인 |
| **학생 1** | `student1` | **[별도 전달]** | 정상 제출, 피드백 반영 후 v2 제출, 반영률 100% 달성 학생 |
| **학생 3, 4** | `student3`, `student4` | **[별도 전달]** | 변수명을 바꾸어 복사 제출한 표절 검사 시연용 학생 쌍 |

> 🔒 **보안 안내**: 심사위원용 계정 비밀번호는 보안상 본 문서에 기재하지 않으며, 심사위원 안내 메일 또는 현장 문서로 **별도 전달**해 드립니다.

---

## 2. 5분 핵심 시연 순서

```
[1. 학생 로그인 & 제출] ──▶ [2. 교수 코드 리뷰] ──▶ [3. 피드백 자동 추적] ──▶ [4. 표절 검사] ──▶ [5. 통계 대시보드]
   (Docker 자동 채점)          (줄 단위 인라인 코멘트)      (Myers Diff 자동 판정)    (Winnowing 핑거프린트)     (Chart.js 인터랙티브)
```

### [1분] 1단계: 학생 제출 및 Docker 자동 채점
1. `student1` 계정으로 로그인합니다.
2. 메인 화면에서 **'자료구조'** 강의 클릭 → **'과제 1 (이진 탐색 트리)'** 선택.
3. **확인 포인트**:
   - 우측 상단 **'남은 피드백'** 카드와 **'테스트 케이스 통과율'** 확인.
   - 하단 제출 폼에서 파일(또는 GitHub 커밋 URL) 제출 시 Docker 격리 컨테이너에서 즉시 컴파일 및 채점되어 버전 번호가 자동 부여되는 흐름.

---

### [1분] 2단계: 교수 줄 단위 코드 리뷰 (GitHub PR 스타일)
1. 상단 내비게이션에서 로그아웃 후, `prof` 계정으로 로그인합니다.
2. **'자료구조'** 강의 → **'과제 1'** → 학생 제출 목록에서 `student1`의 최신 버전을 클릭합니다.
3. **확인 포인트**:
   - 좌측 파일 트리에서 소스 파일 선택.
   - 코드 뷰어에서 **코드 특정 줄(또는 여러 줄 드래그)을 클릭**하면 인라인 피드백 작성창이 열림.
   - 코멘트 작성 ("*예외 처리 보강 및 변수명 수정*") 후 등록 시 GitHub PR처럼 즉시 줄 아래에 배치되는 UX.

---

### [1.5분] 3단계: 피드백 반영 자동 추적 (핵심 혁신 기능)
1. `student1`의 **'제출 이력 타임라인'** 페이지로 이동합니다.
2. **확인 포인트**:
   - **Myers Diff 기반 자동 판정**: 학생이 새 버전을 올릴 때 이전 코멘트 줄의 위치 변화를 추적하여 🔴**미반영** / 🟢**반영됨** / ⚪**삭제됨**으로 자동 판정.
   - 화면 상단에 **'남은 피드백 0개'**, **'피드백 반영률 100%'**가 계산되어 시각적 카드로 표시됨.
   - **'버전 비교(Diff)'** 버튼을 클릭하여 이전 버전과 새 버전 사이의 코드 변화를 좌우 분할(Side-by-Side) 화면으로 직관적 확인.

---

### [1분] 4단계: MOSS 기반 고정밀 표절 검사
1. 상단 과제 메뉴에서 **'표절 검사'** 탭을 클릭합니다.
2. **확인 포인트**:
   - 강의 내 전체 학생 제출물 간의 Winnowing 알고리즘 기반 유사도 매트릭스 확인.
   - 뼈대 코드(교수가 배포한 템플릿)는 검사 대상에서 자동 제외됨.
   - 높은 유사도를 기록한 의심 쌍(`student3` vs `student4`)의 **'비교'** 버튼 클릭:
     - 변수명 변경, 주석 추가, 들여쓰기 조작에도 불구하고 **실제 복사된 핵심 로직이 붉은색 하이라이트**로 나란히 표시되는 정밀 검출 확인.

---

### [0.5분] 5단계: 교수 제출 통계 대시보드
1. 강의 상세 페이지에서 **'통계 대시보드'**를 클릭합니다.
2. **확인 포인트**:
   - 제출률, 미제출자 명단, 지각 제출 비율.
   - 마감 직전 24시간 제출 집중도 그래프 및 시간대별 제출 분포 차트 (Chart.js 인터랙티브 인터페이스).
   - 학생별 총 제출 버전 수와 피드백 반영률 비교 차트.

---

## 3. 화면별 관전 포인트 요약

| 화면 | 주요 URL | 심사위원이 눈여겨보아야 할 포인트 |
|---|---|---|
| **코드 뷰어 / 리뷰** | `/submissions/{id}` | - GitHub 수준의 세련된 줄 단위 인라인 코멘트 및 점수 매기기<br>- 키보드 단축키 및 멀티 파일 탭 전환 |
| **버전 비교 (Diff)** | `/assignments/{a}/students/{s}/diff` | - Myers 알고리즘 기반 빠른 Diff 계산 (최대 편집 거리 상한 보호)<br>- 좌우 분할 / 통합 뷰 및 공백 무시 토글 |
| **피드백 반영 추적** | `/assignments/{a}/students/{s}` | - 코멘트 위치 추적 알고리즘으로 교수 개입 없이 반영 여부 자동 판정<br>- 학생에게 명확한 학습 동기(남은 피드백 수치화) 부여 |
| **표절 검사 쌍비교** | `/similarity/pairs/{id}` | - 변수명 치환(Renaming) 공격을 무력화하는 Winnowing 핑거프린팅<br>- 의심 일치 구간 정밀 나란히 보기 |
| **보안 & 인프라** | `/actuator/health` | - Spring Boot Actuator 정보 은닉 (`status: UP` 만 외부 노출)<br>- 도커 소켓 프록시를 통한 컨테이너 탈출 원천 차단 |
