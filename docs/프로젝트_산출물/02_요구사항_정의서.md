# [산출물 02] 소프트웨어 요구사항 정의서 (SRS: Software Requirements Specification)

> **프로젝트명**: SubmitHub (버전 관리 기반 과제 제출 및 자동 피드백 추적 플랫폼)  
> **문서 버전**: v1.2  
> **작성일자**: 2026-11-07  
> **작성자**: 강서원

---

## 1. 개요 및 시스템 범위

본 문서는 SubmitHub 시스템이 제공해야 하는 모든 기능적(Functional) 및 비기능적(Non-Functional) 요구사항을 구체적으로 정의하고, 각 요구사항이 실제 구현 모듈 및 테스트 케이스와 어떻게 연결되는지 추적성(Traceability)을 보장하기 위해 작성되었습니다.

---

## 2. 기능적 요구사항 (Functional Requirements)

### 2.1. 사용자 인증 및 계정 관리 (FR-AUTH)

| :--- | :--- | :---: | :--- | :--- |
| **FR-AUTH-01** | 회원가입 | Must | • 학생/교수 구분 가입 지원<br/>• 교수 가입 시 관리자 설정 가입 코드(`PROFESSOR_SIGNUP_CODE`) 검증<br/>• 학번, 학과, 이름, 아이디, 비밀번호 입력 | • 입력: 사용자 가입 폼<br/>• 출력: 로그인 페이지 리다이렉트 |
| **FR-AUTH-02** | 사용자 인증 | Must | • Spring Security 기반 Form 로그인<br/>• 비밀번호 BCrypt 일방향 암호화 해싱 적용<br/>• 세션 기반 인증 상태 유지 | • 입력: ID / PW<br/>• 출력: 내 강의 대시보드 |
| **FR-AUTH-03** | 접근 권한 통제 (RBAC) | Must | • `ROLE_PROFESSOR`: 강의 개설, 과제 생성, 줄 코멘트, 표절 검사, 채점 관리<br/>• `ROLE_STUDENT`: 수강 신청, 과제 제출, 내 피드백 열람, 답글 작성 | • 인가 실패 시 403 Forbidden 에러 반환 |

| ID | 요구사항명 | 우선순위 | 상세 기술 | 입/출력 |

### 2.3. 버전 제출 및 파일 파이프라인 (FR-SUBMIT)

| ID | 요구사항명 | 우선순위 | 상세 기술 | 입/출력 |
| :--- | :--- | :---: | :--- | :--- |
| **FR-SUBMIT-01** | 단일 파일 및 ZIP 제출 | Must | • 단일 소스코드 또는 복수 파일 ZIP 아카이브 업로드 지원<br/>• 학생 제출 메모(커밋 메시지 성격) 입력 지원<br/>• 인코딩 자동 판별: UTF-8 및 CP949 자동 디코딩 | • 입력: 파일/ZIP, 메모<br/>• 출력: 새 버전(`vN`) 생성 |
| **FR-SUBMIT-02** | 버전 불변 채번 (동시성 제어) | Must | • 학생별 제출 시마다 버전 번호(`v1, v2, ...`) 자동 증가<br/>• 동시 다발적 연타 제출 시 비관적 락(`SELECT ... FOR UPDATE`) 및 복합 UK(`assignment_id, student_id, version_no`) 충돌 시 1회 자동 재시도<br/>• 제출 데이터는 오직 `INSERT`만 발생 (`@Immutable`) | • 버전 번호 무결성 보장 |
| **FR-SUBMIT-03** | GitHub 커밋 연동 제출 | Should | • 공개 GitHub 저장소 URL 및 브랜치(또는 커밋 SHA) 입력<br/>• GitHub REST API를 통해 해당 시점의 소스 아카이브를 다운로드하여 버전 저장<br/>• 7자리 커밋 SHA, 커밋 메시지, 외부 링크를 영구 보존<br/>• 직전 버전과 동일한 커밋 재제출 시 "변경 없음"으로 차단 | • 입력: repo URL, ref<br/>• 출력: GitHub 메타데이터 바인딩 버전 |

### 2.4. 버전 비교 및 코드 리뷰 (FR-DIFF & FR-REVIEW)

| ID | 요구사항명 | 우선순위 | 상세 기술 | 입/출력 |
| :--- | :--- | :---: | :--- | :--- |
| **FR-DIFF-01** | Myers Diff 비교 엔진 | Must | • 임의의 두 버전(예: `v1 ↔ v3`) 간 파일별 diff 수행<br/>• 좌우 2분할(Side-by-Side) 및 통합(Unified) 뷰 지원<br/>• 공백/들여쓰기 무시 옵션 토글 지원<br/>• 변경 없는 긴 코드 구간 접기(fold) 기능 | • 입력: 버전 A, 버전 B<br/>• 출력: 행별 상태 매핑 뷰어 |
| **FR-REVIEW-01** | 라인 단위 피드백 코멘트 | Must | • 교수는 코드 화면에서 특정 줄 또는 라인 범위(Shift+클릭)를 선택하여 피드백 작성<br/>• 교수와 해당 학생 간의 대댓글(답글) 스레드 지원 | • 입력: 라인 번호, 내용<br/>• 출력: 코드 줄 아래 코멘트 카드 |
| **FR-REVIEW-02** | 피드백 반영 자동 추적 (`LineTracker`) | Must | • 학생이 새 버전 제출 시, 이전 버전의 코멘트 라인 범위를 Myers diff로 추적<br/>• 🔴 **미반영 (`UNCHANGED`)**: 코드가 그대로 남아있음 (줄 번호 밀림 자동 보정)<br/>• 🟢 **반영됨 (`MODIFIED`)**: 코드가 수정/치환됨<br/>• ⚪ **삭제됨 (`DELETED`)**: 해당 코드 블록이 삭제됨<br/>• 학생용 "남은 피드백 N개", 교수용 "피드백 반영률(%)" 자동 집계 | • 입력: 코멘트 + 버전 목록<br/>• 출력: 반영 상태 배지 및 추적 결과 |

### 2.5. 구조적 표절 검사 (FR-SIMILARITY)

| ID | 요구사항명 | 우선순위 | 상세 기술 | 입/출력 |
| :--- | :--- | :---: | :--- | :--- |
| **FR-SIMILARITY-01** | 토큰 정규화 (`CodeTokenizer`) | Must | • Java, C/C++, Python, JS 등 70여 종 예약어 보존<br/>• 식별자 $\to$ `I`, 숫자 $\to$ `N`, 문자열 $\to$ `S` 치환<br/>• 주석 및 공백 완전 제거 (들여쓰기/변수명 위장 무력화) | • 입력: 소스 원문<br/>• 출력: 정규화 토큰열 |
| **FR-SIMILARITY-02** | Winnowing 지문 추출 | Must | • $k=5, w=4 \implies t = 8$ 보장 탐지 임계값 적용<br/>• SplitMix64 해싱 및 로컬 미니멈 윈도잉 지문 추출<br/>• 교수 뼈대 코드(Baseline) 지문 해시 $O(1)$ 사전 필터링 | • 입력: 토큰열, 뼈대코드<br/>• 출력: 유효 Fingerprint 셋 |
| **FR-SIMILARITY-03** | 의심 쌍 대조 뷰어 | Must | • 비대칭 포함도 점수 $\text{Score} = \max(cov_A, cov_B)$ 기반 정렬<br/>• 의심 쌍 클릭 시 2분할 뷰어에서 겹치는 코드 줄 형광펜 하이라이트 | • 입력: 유사도 임계값<br/>• 출력: 표절 순위 리스트 및 대조 뷰 |

## 3. 비기능적 요구사항 (Non-Functional Requirements)

| 영역 | ID | 요구사항 내용 | 검증 기준 및 기술적 조치 |
| :--- | :--- | :--- | :--- |
| **보안** | **NFR-SEC-01** | 타인 제출물 열람 차단 (IDOR 방어) | 모든 조회/수정 요청은 `AccessService`를 거치며, "본인" 또는 "해당 강의 교수"가 아니면 **403 Forbidden** 강제 반환. |
| **보안** | **NFR-SEC-02** | 파일 업로드 공격 원천 차단 | ZIP 압축 해제 시 `..` 경로 조작(Zip Slip) 검증, 디스크 저장은 난수 UUID 파일명 사용. 파일당 5MB, 총 20MB, 파일 수 200개 제한. |
| **보안** | **NFR-SEC-03** | 컨테이너 탈출 방어 (Container Escape) | Docker 데몬 소켓을 직접 마운트하지 않고, `tecnativa/docker-socket-proxy`를 두어 컨테이너 생성/실행 API만 허용하고 볼륨/빌드/네트워크 조작 차단. |
| **보안** | **NFR-SEC-04** | 서비스 거부(DoS) 방어 | Token Bucket 기반 `RateLimitFilter`를 통해 로그인 분당 10회, 제출 분당 5회, AI 호출 분당 3회로 IP/계정별 요청 제한. |
| **성능** | **NFR-PERF-01** | Diff 연산 메모리 최적화 | $O(NM)$ DP 대신 $O((N+M)D)$ Myers Diff를 적용하여 5,000줄 소스코드 비교 시 메모리 사용량을 2MB 이내로 억제 (LCS 97MB 대비 99% 절감). |
| **성능** | **NFR-PERF-02** | 대용량 파일 보호 (OOM 차단) | 12,000줄 이상 또는 100만 회 초과 변경 발생 시 diff 연산을 `truncated=true`로 즉시 중단하고 안전 폴백(Fallback) 처리. |
| **무결성** | **NFR-DATA-01** | 제출 이력 불변성 보장 | 제출 테이블은 `INSERT` 전용으로 운영되며, 기존 버전의 `UPDATE`나 `DELETE`를 일체 허용하지 않음 (`@Immutable`). |
| **가용성** | **NFR-AVAIL-01** | Docker 무설치 환경 정상 동작 | Docker 데몬이 없는 PC에서는 채점 기능만 `UNAVAILABLE`로 비활성화되고, 제출/diff/리뷰/표절 검사 등 모든 핵심 기능은 정상 동작. |
